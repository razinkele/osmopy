# osmopy (OSMOSE Python) — Literature Alert & Implications

**Window:** 2026-05-26 → 2026-06-30 (monthly scheduled run)
**Tool:** OSMOSE Python — multispecies / community marine-ecosystem simulator (pure-Python NumPy+Numba engine, Java-parity; Shiny-for-Python UI). Baltic Sea example (8 species: cod, herring, sprat, flounder, perch, pikeperch, smelt, stickleback + 6 LTL groups, 50×40 grid) validated vs ICES SAG. Calibration via pymoo NSGA-II + GP surrogate + SALib Morris/Sobol; CMEMS forcing via the Copernicus MCP. Engine processes in `osmose/engine/processes/` (growth, predation, mortality, reproduction, movement, fishing); outputs via `osmose/engine/output.py`. Repo: https://github.com/razinkele/osmopy
**Sources:** scite (peer-reviewed), ICES Library / FishSec / HELCOM, CRAN, GitHub osmose-model org + homepage. Paper links resolve via the Klaipėda University library proxy.

> **Headline this month: OSMOSE core shipped two releases — v4.4.0 (21 May 2026) and v4.4.1 (18 Jun 2026).** osmopy targets the 4.3.3 JAR, so the port is now two minor versions behind, with several **breaking API/config changes and new engine processes**. This is the dominant action item; the literature side was thin (most scite hits were off-topic — parasitology, eDNA, reef ecology, ML/CS, the Atlantis myth — and were dropped), with two genuinely new modelling papers worth noting.

## Items this window

### OSMOSE upstream (most important)
1. **OSMOSE 4.4.0 — major Java release** (osmose-model/osmose, tag `v4.4.0`, released 2026-05-21 by barriern). Architectural + biological + economic overhaul: region-aware mortality (`nDead`/`ageDeath` now 2-D `[region][cause]`); fishing & discards tracked in **numbers** not biomass (`fishedBiomass→fishedAbundance`, API `fishedBy()→fishedNBy()`); `incrementNdead()` now requires a timestep arg; **stochastic maturity ogive** reproduction (`species.maturity.l50/l75`); new spherical egg-size bioenergetics (`species.egg.density`); **post-reproduction mortality** (iteroparous/semelparous); simplified bioenergetics when data-poor (`species.bioenergetics.model = full|simple`, temperature tmin/topt/tmax); **background-species overhaul** (background groups are now real schools driven by CSV/NetCDF maps, always included in outputs); **gradient-based movement**; LTL predation log option (`simulation.resources.computePercent.legacy`); functional **bioeconomics module**; deterministic seed mode (`simulation.fixed.seed.enabled`); large breaking config-key migration (`module.bioenergetics.enabled`, `module.genetics.enabled`, `module.multispecies.fisheries.enabled`, `simulation.restart.*`); NetCDF chunking default changed. <https://github.com/osmose-model/osmose/releases/tag/v4.4.0>

## Implications for osmopy

- **OSMOSE 4.4.0/4.4.1 parity is now the top concern (items 1–2).** osmopy advertises Java-parity against 4.3.3; upstream has moved two minor versions with **breaking** changes that touch nearly every engine process and the output layer:
  - **`mortality` + `output.py`:** mortality is now region-aware (`nDead`/`ageDeath` 2-D `[region][cause]`) and `incrementNdead()` is timestep-aware. osmopy's mortality-by-cause outputs and any region-resolved diagnostics need a parity review. CHALLENGES current parity.
  - **`fishing` + outputs:** fishing/discards moved from biomass to **abundance** as the primary quantity (biomass derived on demand). osmopy's fishing process and CSV/NetCDF fishing outputs should mirror this to stay comparable. CHALLENGES parity.
  - **`reproduction`:** new **stochastic maturity ogive** (`l50/l75`, normal-CDF maturation) and **post-reproduction mortality** (semelparous/iteroparous) — directly relevant to the Baltic config, where smelt and three-spined stickleback have short, semelparous-leaning life histories. EXTENDS the reproduction process.
  - **`predation` (LTL):** new log-form `computePercent` for the fraction of an LTL group eaten — bears on osmopy's LTL/CMEMS forcing coupling. EXTENDS.
  - **`movement`:** new gradient-based movement and NetCDF-map background distributions. EXTENDS.
  - **bioenergetics:** simplified data-poor mode (`full|simple`, temperature tmin/topt/tmax) is a tractable on-ramp for temperature physiology in the Baltic config without full Bioen parameterization. EXTENDS.
  - **reproducibility:** `simulation.fixed.seed.enabled` (deterministic RNG across movement/reproduction/genetics/forcing/selectivity) is a near-free win for osmopy's test suite — deterministic runs make the ICES-SAG validation and unit tests far more stable. VALIDATES/ENABLES testing.
  - **config migration:** the renamed keys (`module.*.enabled`, `simulation.restart.*`, de-`bioen`-prefixed maturity/ingestion keys) will need mapping if osmopy ingests or emits OSMOSE-style config files — a compatibility-shim candidate.
- **Atlantis semi-automated calibration framework (item 3)** is a peer comparator for osmopy's pymoo NSGA-II + GP-surrogate + SALib pipeline — a citable benchmark/motivation and a possible source of staged-calibration tactics (e.g. parameter grouping, sequential target weighting) to document in `docs/`. VALIDATES the calibration agenda.
- **Prey-specialization × rebuilding plans (item 4)** suggests a scenario diagnostic: run osmopy Baltic fishing-recovery scenarios with predation on vs off and report how cod/clupeid rebuilding trajectories diverge by prey specialization — a multispecies-specific use of the emergent predation-mortality outputs. EXTENDS (scenario diagnostic).
- **Baltic calibration refreshes from last month still stand (items 6–7).** The May-2026 ICES advice cycle and WGSAM SMS predation-M series remain un-ingested; these carry forward as High items (see proposed-issues.md, already drafted).
- **mizer / EwE unchanged (items 10–11).** No code action; remain cross-model comparators only.
