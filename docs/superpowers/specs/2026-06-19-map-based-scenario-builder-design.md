# Map-Based Scenario Builder — Design

> A Shiny tool to author OSMOSE spatial grid maps (species distribution/movement maps, the land mask, or generic zones) by **drawing on a georeferenced map** — polygon-fill + cell-brush — and save them as the `;`-separated grid CSVs the engine reads, with type-aware config wiring. Closes a real gap: today these maps are hand-crafted offline.

## Goal

A new "Map Builder" UI page where a user draws regions/cells on the loaded config's georeferenced grid and the tool writes a standard map CSV + wires it into the config (a distribution `movement.file.map{N}` with applicability, the `grid.mask.file`, or a bare zone CSV). Works for both engines (the output is a plain config map; no engine change).

## Scope

In scope: a **general grid-map painter** for all OSMOSE grid-CSV map types (distribution/movement, land mask, generic zone); **polygon-draw + cell-brush**; **numeric paint value (default 1) + an editable land mask**; **save CSV + type-aware config wiring**. Built on `shiny_deckgl` (approach A — native interactive map).

Out of scope (YAGNI): spatial-fishing/MPA effort mechanics beyond a generic zone CSV; multi-map batch editing; undo/redo history beyond a single clear/reset; authoring the grid bounds themselves (the grid is taken from the loaded config); 4.4.0-specific map features.

## Background (verified)

- OSMOSE spatial maps are georeferenced grid CSVs: `nlat` rows × `nlon` cols, `;`-separated, `-99` = land/masked, otherwise a presence/probability value (e.g. Baltic = 40×50; `data/baltic/maps/cod_adult.csv` is all `1`/`-99`). The grid is georeferenced via `grid.upleft.{lat,lon}` / `grid.lowright.{lat,lon}` + `grid.nlon`/`grid.nlat`; land from `grid.mask.file`.
- Distribution maps are wired via `movement.file.map{idx}` + per-map applicability — the REAL keys (verified in `osmose/schema/movement.py` + read at `osmose/engine/movement_maps.py:128-178`): `movement.species.map{idx}` (single species name), `movement.steps.map{idx}`, `movement.initialage.map{idx}`/`movement.lastage.map{idx}`, `movement.initialyear.map{idx}`/`movement.lastyear.map{idx}` (lastyear inclusive) or `movement.years.map{idx}`. (NOT `movement.map{idx}.*` — that inverted form is a known no-op bug the schema warns about.) Maps are discovered by iterating `movement.species.map{N}`. CSV maps are stored **south-row-0** on disk; the reader flips (`np.flipud` / `ny-1-csv_row_idx`).
- `shiny_deckgl` supports drawing natively: `DrawMode.{DRAW_POLYGON,DRAW_RECTANGLE,...}`, `pickable` layers, `info_widget` (pick) — it is interactive, not render-only. `ui/pages/grid_helpers.py::build_grid_layers` already maps a grid → per-cell lat/lon polygons (georeferencing solved); `load_mask` reads the base mask. `ui/pages/map_viewer.py` shows the established render pattern + view-state.

## Architecture

Two new units + reuse of existing spatial infra, splitting all browser-independent logic into a pure core:

- **`osmose/maps/builder.py`** — pure, Shiny-free, fully unit-testable: grid geometry, rasterization, paint/erase/mask ops, CSV (de)serialization, validation, and the config-wiring key computation.
- **`ui/pages/map_builder.py`** — the Shiny page: interactive deck.gl map (draw + brush), controls, reactive grid state, save handler. Thin; delegates to the core.
- **Reuse:** `ui/pages/grid_helpers.py` (`build_grid_layers`, `load_mask`), `ui/state.py` `AppState`, `osmose/schema/movement.py` field defs, the `map_viewer` view-state conventions.

### `osmose/maps/builder.py` — interface

- `GridSpec` (dataclass) — from `state.config`: `nlon, nlat, upleft_lat, upleft_lon, lowright_lat, lowright_lon`. Derived (`dx=(lr_lon-ul_lon)/nlon`, `dy=(ul_lat-lr_lat)/nlat`): `cell_centers() -> (lat_2d, lon_2d)` with center of `(r,c)` = `(ul_lat-(r+0.5)*dy, ul_lon+(c+0.5)*dx)`; `cell_polygon(r,c) -> [[lon,lat]×4]` + `cell_polygons()`. **DRY (review H1):** this cell-geometry math currently lives inline in `grid_helpers.build_grid_layers` (grid_helpers.py:339-348). Factor it into `GridSpec` (the single source of truth) and have `build_grid_layers` CALL `GridSpec.cell_polygon` to build its `data` — so the core and the renderer can't drift. **This is the ONLY change to shipped code** — `build_grid_layers`'s output (per-cell dict keys `polygon`/`row`/`col`/`type`, corner order `[UL,UR,LR,LL]`, north-row-0, ocean/land layer split) must stay byte-identical; its only real consumers are `grid.py:570` + `map_viewer.py:280`, and the existing `tests/test_ui_grid.py` corner/orientation + layer-split assertions are the de-facto characterization test — they MUST stay unmodified and green post-refactor. **Row/orientation: the in-memory array is NORTH-row-0** (row 0 = `upleft`/northernmost), matching `build_grid_layers`.
- `MapGrid` (wraps an `np.ndarray` shape `(nlat, nlon)`, **north-row-0**, land = `-99`):
  - `apply_cells(cells: Iterable[(row,col)], value: float) -> None`
  - `apply_polygon(grid_spec, polygon_lonlat, value, *, mask_edit=False) -> None`
  - `erase(cells) -> None` (→ `0`)
  - `set_mask(cells, masked: bool) -> None` (→ `-99` or `0`)
  - `array -> np.ndarray`
- `rasterize_polygon(grid_spec, polygon_lonlat, mask, *, mask_edit=False) -> list[(row,col)]` — point-in-polygon (cell center inside the ring) via a **numpy ray-cast** helper, NOT `matplotlib.path.Path` (review: matplotlib is only a TRANSITIVE dep, undeclared in `pyproject.toml` → a clean-venv/CI import trap; the ray-cast keeps the shipped `osmose/maps/builder.py` dependency-free). Excludes `-99` cells unless `mask_edit`. Center-in-polygon is the sole rule (no overlap-mode — YAGNI). No cell center inside → empty list (UI info toast). The input ring is the GeoJSON outer ring (lon,lat order, closed — drop the duplicated closing point). (Wrap the ray-cast division in `np.errstate(divide="ignore", invalid="ignore")` — horizontal polygon edges otherwise emit a benign divide-by-zero warning; the result is unaffected.)
- `lonlat_to_cell(grid_spec, lon, lat) -> (row,col) | None` — maps a clicked basemap coordinate to a north-row-0 cell (for brush via `_map_click`); `None` if outside the grid.
- `to_csv_text(map_grid) -> str` / `from_csv_text(text, grid_spec) -> MapGrid` — **CRITICAL orientation:** the engine map-CSV file is SOUTH-row-0 (`movement_maps._load_csv_grid` does `grid_row = ny-1-csv_row_idx`; `load_mask`/`load_csv_overlay` `np.flipud`). The in-memory array is north-row-0, so `to_csv_text` must `np.flipud` (north-row-0 → south-row-0 file) and `from_csv_text` must `np.flipud` back. `;`-separated, `-99` land. `from_csv_text` validates dims == `(nlat, nlon)` (raises `ValueError`). The round-trip test asserts a written CSV, read by the ENGINE's `movement_maps._load_csv_grid`, reproduces the painted north-row-0 grid (NOT just self-round-trip — that would pass while flipped).
- `validate(map_grid, grid_spec) -> list[str]` — dim mismatch; for mask saves, mask cells inconsistent with the grid; for distribution/zone, WARN (not block) where a value is painted on a base-mask land (`-99`) cell (the engine treats those as absent regardless).
- `wire_map_into_config(config, map_type, rel_path, *, applicability=None) -> (new_config, summary)` — pure. Distribution → next free index across the WHOLE `map{N}` family (engine discovers maps via `movement.species.map{N}`) + the REAL keys from `applicability`: `movement.species.map{N}` (single species name — case-insensitively matched, `movement_maps.py:131`), `movement.file.map{N}=rel_path`, optional `movement.steps.map{N}` (`;`-sep season step indices), `movement.initialage.map{N}`/`movement.lastage.map{N}` (years, float), `movement.initialyear.map{N}`/`movement.lastyear.map{N}` (lastyear INCLUSIVE, `movement_maps.py:173-175`) or `movement.years.map{N}`. **One species per map** (the key is a single string, no list form). To apply one drawn file to N species, emit N `map{N}` blocks sharing `rel_path`. Mask → `grid.mask.file = rel_path`. Zone → no keys. **Applicability defaults** (so a species-only save produces a working all-ages/all-seasons map matching engine defaults): pre-fill `initialage=0`, `lastage=lifespan`, all season `steps`, all `years`. **Always emit `movement.steps.map{N}`** (all steps if unspecified) — otherwise `grid_helpers.build_movement_cache` skips the map in the movement overlay (`if not steps: continue`), so a correctly-wired map would be invisible after save (review 3c). All emitted keys are schema-defined in `schema/movement.py`, so `EngineConfig.from_dict` validation already accepts them (no `_SUPPLEMENTARY_ALLOWLIST` change). Returns updated config + a human summary.
- `save_map(map_grid, grid_spec, map_type, filename, config, config_dir, *, applicability=None) -> (new_config, summary, written_path)` — **pure orchestration** (the file write + `to_csv_text` + `wire_map_into_config`), so the save path is unit-testable WITHOUT a Shiny mock-session (review H2: the suite has no session harness — existing ui tests test extracted pure functions). Sanitizes `filename` (reject empty / path-separators / `..` / non-`.csv`; the engine's `resolve_data_path` rejects `..` but we must not write a bad file first). The reactive Save handler just calls this + toasts.

### `ui/pages/map_builder.py` — page

- New nav entry "Map Builder" (navset_pill_list). **Registration is manual (4 touch-points in `app.py`, no auto-discovery):** (1) `from ui.pages.map_builder import map_builder_ui, map_builder_server`; (2) `ui.nav_panel("Map Builder", map_builder_ui(), value="map_builder")` inside `navset_pill_list`; (3) `map_builder_server(input, output, session, state)` in `server()`; (4) add `"map_builder"` to the JS nav-order array at `app.py:235`. On entry: read grid from `state.config` → `GridSpec` + base mask (`load_mask`, which returns `None` when no `grid.mask.file` → all-sea grid, all cells paintable). No grid → hint + disabled.
- **Species selector source (review C1 — the no-match footgun):** populate from `species.name.sp{i}` for `i in range(int(simulation.nspecies))` (the established pattern, `grid.py:854-857`); the selected NAME is written verbatim as `movement.species.map{N}` (engine matches by name, case-insensitive). NEVER a free-text field.
- **Start controls:** "New blank map" (seed base mask → `-99`, else `0`; all-sea if no mask) | "Load existing map…" (select a `movement.file.map{N}`/`grid.mask.file` → `from_csv_text`, which flips to north-row-0 for display — must match what `map_viewer`/`load_csv_overlay` show).
- **Tool mode:** Polygon-draw | Brush | Eraser | Mask-edit. **Paint value:** numeric (default `1`; graded values rendered via the existing `load_csv_overlay` value→RGBA ramp, `grid_helpers.py:736-745`).
- **Map-type selector:** Distribution | Land mask | Generic zone — drives Save. **Distribution applicability form:** species (required, single), initial/last age, season steps, initial/last year — reuse `schema/movement.py` renders. (Multi-species → N blocks is deferred v1.x.)
- **Interactive map:** `build_grid_layers` cells over the basemap. **Draw** = MapboxDraw via `await MapWidget.enable_draw(session, modes=["draw_polygon"], default_mode="draw_polygon")` (runtime, not a layer prop) → `input.{id}_drawn_features()`. **Brush/eraser/mask** = `input.{id}_map_click()` (lon/lat) → `lonlat_to_cell`. (`info_widget` is display-only — not a read-back channel.)
- **Draw semantics — STAGE-then-APPLY (review CRITICAL-1/-2, the real bug):** `_drawn_features` delivers the CUMULATIVE FeatureCollection (`draw.getAll()`) on every create/update/delete, and clearing it re-fires the event (empty). So `@reactive.event(input.{id}_drawn_features)` must ONLY update a `reactive.Value` staged-set + an "N staged" indicator (empty payload = no-op) — it must NOT paint. An explicit **"Apply polygon(s)"** button: rasterizes only features whose `feature.id` is not in an `applied_ids` `reactive.Value[set]` (defense vs re-fire), captures the paint value AT APPLY TIME, applies, then `await _map.delete_drawn_features(session)` and resets `applied_ids`. (Applying on the raw event would re-paint earlier polygons at the current value — silent corruption.)
- **Tool-mode ↔ draw toggle (review CRITICAL-3):** a `@reactive.effect` on the tool-mode selector → Polygon mode `await _map.enable_draw(...)`, Brush/Eraser/Mask `await _map.disable_draw(session)` (else MapboxDraw swallows brush clicks / brush clicks place phantom vertices). The `_map_click` handler ALSO early-returns when mode != brush/eraser/mask (`_map_click` fires on every click regardless).
- **Init race (review IMPORTANT-2):** gate `enable_draw` + the initial layer render on `input.deckgl_ready` (mirror `grid.py:500-505`; early calls are silently dropped by the JS `if(!instance)` guards). Read config under `reactive.isolate()` so config-form keystrokes don't wipe in-progress painting.
- **Render (review IMPORTANT-1):** brush/apply mutate the `reactive.Value[np.ndarray]` immediately (cheap); the deck render is decoupled + COALESCED — a dirty-flag bumped per op + a debounced/`reactive.poll`-style effect that re-renders only when dirty, using `partial_update(session, layers=[grid_cells_layer])` (touch ONLY the grid layer, not the whole stack). No per-cell patch API exists — the grid layer is the redraw granularity; coalescing avoids re-serialising 2000+ cells per click.
- **Save:** filename input → `save_map(...)` (sanitizes name; `to_csv_text` flipped to south-row-0; writes `state.config_dir/maps/<name>.csv`; `wire_map_into_config` with relative `maps/<name>.csv`) → apply via `AppState` → reload. Warn on overwrite + on a duplicate distribution map whose species+age+step range overlaps an existing block (engine lets the last-loaded map win via `index_maps` overwrite). Toast on success.

## Data flow

`state.config` (grid bounds + mask) → `GridSpec` + base mask → init `MapGrid` (blank or loaded) → `reactive.Value[ndarray]` → [polygon: draw → STAGE → Apply button → `rasterize_polygon`→`apply_polygon` (new feature-ids only) → clear draw layer; brush/eraser/mask: `_map_click` → `lonlat_to_cell` → `apply_cells`/`erase`/`set_mask`] → dirty-flag → coalesced `partial_update` of the grid layer → Save → `save_map` (`to_csv_text` flip + write `state.config_dir/maps/` + `wire_map_into_config`) → apply via `AppState` → reload.

## Error handling / edge cases

- No grid / malformed bounds → builder disabled, hint "Load a config with a defined grid first."
- Paint a value on a land (`-99`) cell → blocked unless Mask-edit mode (the explicit land/sea change path).
- Mask save → `validate` dims == `grid.nlon×nlat` (don't produce a mask inconsistent with the configured grid).
- Polygon entirely outside the grid → 0 cells matched → info toast, no-op.
- Distribution map saved with no species selected → block with a clear message (an unapplied map is a silent footgun).
- Invalid filename (empty / spaces / path-separator / `..` / non-`.csv`) → sanitized + blocked by `save_map` before any write.
- No `grid.mask.file` (all-sea grid) → `load_mask` returns `None`; blank seed = all `0` (no land), all cells paintable, the paint-on-land guard is inert.
- Duplicate distribution map (same species + overlapping age/step range as an existing block) → warn (engine lets the last-loaded overlapping map win via `index_maps` overwrite).
- Overwriting an existing map file → confirm.
- **Map-file location + run-time resolution (RESOLVED by review — was the flagged risk):** demos are loaded into a WRITABLE per-session temp copy (`osmose/demo.py` copytrees `data/<config>` → `/tmp/osmose_demo_*/config/`), and `state.config_dir` points there — NOT the read-only repo. So write the CSV to `state.config_dir/maps/<name>.csv` and register the **relative** path `maps/<name>.csv` (never absolute; no `..` — `path_resolution.resolve_data_path` rejects `..`). This resolves for all three consumers: the in-UI overlay render (`grid.py` requires the file under `state.config_dir`), the Python engine (resolves `movement.file.map{N}` relative to `_osmose.config.dir` = `state.config_dir`), and the Java engine (`write_temp_config` copytrees the whole config dir — maps included — into the run temp dir before invoking the jar). The file MUST exist on disk under `state.config_dir` before a run (write_temp_config copies what's present; it doesn't fetch missing files).
- **`state.config_dir is None`** (config built from scratch / reset, never loaded from a demo) → the builder must create a session temp dir, `state.config_dir.set(it)`, and write there; or, if no writable dir can be established (`os.access` check fails), disable Save with a clear message.

## Testing strategy

- **Pure core (CI — the bulk):** `rasterize_polygon` (concave polygons, cells on polygon edges, Baltic-style bounds, polygon outside grid); `lonlat_to_cell` (incl. outside-grid → None); `apply_cells`/`erase`/`set_mask`; **CSV orientation via the ENGINE:** `to_csv_text` → write to a `tmp_path` file → `movement_maps._load_csv_grid(path, nlat, nlon)` (it reads a FILE PATH, returns the array — NOT text) → assert it reproduces the painted north-row-0 grid (catches a flip; self-round-trip would not). `from_csv_text` round-trip + dim validation must reject too-MANY columns (`_load_csv_grid` only errors on too-few). `validate` (dim mismatch, mask consistency, distribution-on-land warning). `GridSpec` geometry — since `build_grid_layers` now CALLS `GridSpec.cell_polygon` (DRY H1), assert the shared helper directly; the renderer is correct by construction. Property test (Hypothesis, **in-memory only — no `tmp_path`/fixtures under `@given`**): the rasterized cell set == exactly the cells whose center is inside the polygon. `wire_map_into_config` — REAL keys (`movement.species.map{N}` single string + `movement.file/initialage/lastage/initialyear/lastyear/steps/years.map{N}`), next-free index across the whole `map{N}` family, `grid.mask.file` for mask, no keys for zone, `steps` always emitted.
- **`save_map` (pure orchestration — no browser):** given a MapGrid + type + filename + config + a tmp config_dir, asserts it writes the CSV under `maps/` and returns the right config keys; filename sanitization (reject `..`/separators/non-csv); re-applying a draw event with a SUPERSET of feature-ids does NOT re-paint already-applied features (the stage-Apply id-diff). This is the testable surface that replaces an (unavailable) Shiny-session harness.
- **UI:** `import ui.pages.map_builder` clean; `app.py` registration present (the 4 touch-points).
- **deck.gl draw/pick event binding** (the one hard-to-unit-test seam) → e2e/visual Playwright + manual; all event→cell logic lives in the pure core, tested independently of the widget.
- Full suite green; ruff + pyright clean. New runtime deps: NONE (numpy ray-cast, no matplotlib/shapely).
