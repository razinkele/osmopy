Three durable lessons from the FishBase-bootstrap subagent-driven run (PR #69, master `3afae99`, 2026-06-17). Per-task implementer subagents ran `ruff` + tests and reported green; the FINAL verification still caught all three. **The fix each time: run the full gate set yourself between/after tasks — don't trust per-task self-reports.**

**1. Per-task review gates MUST include pyright, not just ruff.** This has now recurred TWICE (scenario-diff PR #60, then FishBase PR #69). The FishBase client was ruff-clean + 15 tests green per the implementer, but `pyright` found **60 errors** — pandas/pyarrow reductions (`Series.median()/.min()/.max()`, `itertuples()`, `pd.to_numeric`) return broadly-typed objects the stubs can't narrow, so they aren't cleanly `float()`-castable. CI's `type-check` job is REQUIRED and would have failed. **Fixes for the pandas-stub grind:** reduce on a plain `np.asarray(series, dtype=float)` (numpy reductions are cleanly typed) rather than Series methods; `cast("pd.DataFrame", df[mask])` for boolean-index results; use `df.to_dict("records")` instead of `itertuples()` (pyright types tuples' attrs as unknown); `cast("pd.Series", pd.to_numeric(...))`. Always run `PYRIGHT_PYTHON_FORCE_VERSION=latest .venv/bin/pyright <changed files>` before declaring a task done. Related: [[feedback_ci_pyright_reproduction]], lint is BOTH check+format [[feedback_ci_lint_is_check_plus_format]].

**2. `git add file1 missing-path file2` ABORTS without staging ANYTHING.** A bad/non-existent pathspec makes `git add` fatal *before* staging the valid paths, so a subsequent `git commit` records nothing new (or only what was already staged). On PR #69 I ran `git add … tests/test_fishbase_e2e.py …` AFTER a `git mv` had already renamed that file → "fatal: pathspec … did not match" → the `ruff format` changes I intended to commit were silently NOT staged; the commit (message claimed the fix) contained only the prior `git mv` rename → CI lint failed again on the still-unformatted files. **Symptom: `git status` shows files still Modified right after a commit you thought included them.** Always re-check `git status --short` after a commit; never list an already-renamed/deleted path in `git add`.

**3. e2e test files MUST be named `test_e2e_*.py`** (NOT `test_*_e2e.py`). `tests/conftest.py` does `collect_ignore_glob.append("test_e2e_*.py")` when `find_spec("playwright") is None`. Playwright lives in the `[viztest]` extra, NOT `[dev]`, so CI's `test` job has no playwright. Any e2e file that does a module-level `from playwright.sync_api import …` but does NOT match the `test_e2e_*.py` glob is collected → `ModuleNotFoundError` during collection → the whole `test` job errors (marker `-m 'not e2e'` deselection happens AFTER import, too late). My `test_fishbase_e2e.py` failed collection; renaming to `test_e2e_fishbase.py` fixed it. Mirror the existing `test_e2e_*.py` convention for any new e2e test. Related clean-venv theme: [[feedback_ci_clean_venv_reproduction]].

**Meta:** these are exactly the "per-task gates ran ruff but not pyright / didn't reproduce CI" class. When driving subagents, the controller's between-task verification should mirror the EXACT CI gate set (ruff check + ruff format --check + pyright over changed files + the targeted tests), and re-confirm `git status` after each commit.
